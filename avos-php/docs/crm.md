# AV OS — CRM & Business

## Lead flow (public website → CRM)

```
Visitor → contact/booking form → POST /api/public/lead
  → validation (name, email format, length caps)
  → spam protection (honeypot, optional Cloudflare Turnstile, per-IP 10/15min,
     per-email 5/h)
  → MySQL leads (UTMs, page, referrer, source captured)
  → configurable scoring (lead_scoring_rules → score 0-100, priority)
  → automation (lead.created) + notifications + signed webhooks
  → confirmation email queued to visitor + admin alert (best-effort, never blocks the lead)
  → Calendly continuation on the site (popup + graceful fallback links; CRM save never depends on Calendly)
```

## Objects

- **Leads** — lifecycle: new → contacted → qualified → proposal → won/lost/archived; score, tags,
  notes, UTM attribution, `updated_at` (drives inactivity).
- **Contacts / Companies** — CRM directory; company ← contact.
- **Opportunities** — pipeline: new/contacted/qualified/meeting/proposal/negotiation/won/lost/archived
  with value, probability, expected close, source, campaign. Stage changes logged via activities + audit.
- **Meetings** — subject, scheduled_at, duration, type, status
  (scheduled/confirmed/completed/cancelled/no-show/rescheduled), notes, outcome; Calendly sync-ready
  (integration hook), manual management fully supported.
- **Tasks** — follow-ups tied to any entity (lead/meeting/opportunity/project), priority.
- **Activities** — timeline per entity.

## Lead scoring

Rules live in `lead_scoring_rules` (match_field: email_domain / lead_type / project_type / source /
referral / timeline / budget; points; sort). Not hardcoded — editable via the CRM scoring UI.
Verified: experience-centre project type → score 85.

## Campaign attribution

`campaigns` table (UTM triplet, status, budget, period, description) + reporting:
visitors and leads per campaign (from `analytics_events` + `leads.utm_campaign`).

## Proposals

Proposals carry scope, deliverables, timeline, investment (currency), terms, validity days and
status (draft/sent/viewed/accepted/rejected/expired). HTML preview + **PDF export** generated by a
pure-PHP PDF writer (`backend/core/Pdf.php` — no Composer, Hostinger-safe; verified with poppler).

## Business projects

Company → Opportunity → Business Project (+ milestones, documents) → published case study.
Case studies on the public site come from `content_store.projects`.

## Follow-up automation (lead.inactive)

- Trigger `lead.inactive` with condition `days_min` (default 7).
- Sweep: `POST /api/automations/check-inactive` (admin UI button) or cron
  `php backend/cron/lead-inactivity.php` (Hostinger cron-compatible, daily/hourly safe —
  each lead fires at most once per 24h per rule).
- Actions: notification (variables rendered), follow-up task, follow-up email
  (`follow_up` template), webhook.

## Email engine

`email_templates` (7 seeded, CMS-editable with `{variables}`) → `email_log` queue + best-effort
`mail()` delivery with status. SMTP can be layered via integration config without changing the
contract. Credentials never reach the frontend.

## V3 CRM

- **Soft delete + restore**: all CRM entities trash/restore/permanent-delete; Leads UI has a trash
  view with restore + permanent delete.
- **Activity timeline**: every important event is recorded (`created`, `status_changed`,
  `meeting_scheduled`, `proposal_created`, `resubmitted`) and shown in the lead detail modal.
- **Idempotency**: repeated submissions with the same email within 24h return the existing lead
  (`duplicate: true`) and log a `resubmitted` activity instead of creating duplicate rows.
- **Pagination/filters/export**: leads API supports limit/page/status/search/sort + formula-safe CSV.
