### The one remaining blocker (pre-existing, NOT introduced by Phase 5)

`/api/v1/content` and `/admin/login.php` return **HTTP 500 — "AV OS is not
configured for production: database credentials not configured · AV_ENC_KEY
must be set"**. This is the **same backend provisioning blocker documented
since Phase 3**: Hostinger staging has no MariaDB + `config.local.php` +
`AV_ENC_KEY` provisioned. It requires the manual hPanel steps in
`STAGING-BACKEND-RUNBOOK.md` (create the staging DB, upload `avos-data/site.json`,
place `config.local.php` at the account root, run `database/install.php`).

**Consequence:** the public site is fully functional (it renders the
prerendered static snapshot — the designed fallback — so it works even with the
API down). The React admin *shell* is deployed, but its login/data operations
cannot succeed until the backend DB is provisioned on Hostinger. This is a
**hosting-provisioning** task, not a code task, and I have no Hostinger access
from this environment.
